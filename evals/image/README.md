# Image generation — evaluation harness

A run answers one question: **did this change make the output better, and what did
it cost?** Every cell records the model, the compiled prompt, the references and
their roles, the brand inclusions, the credits charged, the latency and the
failure reason — so two runs are comparable on something other than memory.

## Running it

```bash
# Zero credits, zero network. This is the CI gate.
npm run eval:image

# Prompts only, real compiler, no images.
npm run eval:image -- --stage=compile --mode=mock

# Real provider calls. Priced by the SERVER and refused before the first paid
# call if the total exceeds the budget.
JWT=<user access token> BRAND=<brand uuid> \
  npm run eval:image -- --mode=live --tasks=ab \
    --models=google:nano-banana --budget-credits=20
```

`JWT` must be a signed-in user's Supabase access token — the anon key alone is
refused for anything that spends money. In the app, signed in:

```js
JSON.parse(localStorage['sb-ciojgoozobzbeglwdxcz-auth-token']).access_token
```

`BRAND` must be a Supabase **uuid**; a local `brand_…` id fails the access check.

## Comparing against the pre-change compiler

`--baseline-dir` points at a directory holding the OLD compiler, so a "before"
column is generated by real code rather than remembered. Materialise it from any
git ref:

```bash
mkdir -p evals/image/.baseline
git show <ref>:src/features/editor/ai/imagePrompt/artDirection.ts \
  | sed "s#from './brandImageContext'#from '@/features/editor/ai/imagePrompt/brandImageContext'#" \
  > evals/image/.baseline/artDirection.old.ts
git show <ref>:src/features/editor/ai/imagePrompt/compileImagePrompt.ts \
  | sed "s#from './artDirection'#from './artDirection.old'#" \
  | sed "s#from './brandImageContext'#from '@/features/editor/ai/imagePrompt/brandImageContext'#" \
  > evals/image/.baseline/compileImagePrompt.old.ts

npm run eval:image -- --stage=compile --mode=mock --baseline-dir=evals/image/.baseline
```

It is NOT committed: it is a reconstruction, it is regenerable in two commands,
and a stale copy of an old compiler sitting in the tree is a thing someone will
eventually import by accident. `vite-node` restarts if it is placed outside the
repo, which is why the path is inside it.

## What is scored

`score/heuristic.ts` — deterministic, free, and the only thing allowed to fail a
run. A multimodal critic is a non-deterministic judge, and a judge that can turn
the build red on its own eventually will, for no reason. The critic
(`src/features/editor/ai/imagePrompt/critique.ts`) is an opt-in signal, run
offline over recorded images so a critic change can be re-scored at zero image
cost.

Two signals are worth knowing about because they encode measured failures:
`notProhibitionHeavy` (the old brief spent ~40% of its words forbidding things,
and sent the ban list twice) and `notBloated` (**both** pipelines still fail
this — the threshold is 320 words and neither is under it).

## Cost, honestly

The charge is derived from the workspace balance DELTA, read from
`credit_accounts` between calls. An earlier version of `transport.ts` invented a
`charged` field the server does not return, recorded `0` for every cell, and
would have reported a fully paid run as free.
